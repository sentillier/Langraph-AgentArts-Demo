# 智能体评估（Evaluation）

> **官方材料基线**：0916《观测与优化智能体》**第 2 章「智能体评估」**（117–296 页）。
>
> **0916 变更点**：评估器总数由 51 个增至 **52 个**（新增 **Token 效率**）；评估章节与优化章节形成官方闭环（评估结果可回流至评测集，并作为轨迹分析/工具优化/Skill 优化/模型优化的数据源）。评估任务结果支持**标注**与**回流**。

## 1. 评估模型

智能体评估是按预设标准对输出质量、正确性、工具调用合理性等维度进行系统化、自动化检验的过程。

```text
评测集（考卷） + 评估对象（考生） + 评估器（阅卷官）
                               ↓
                       评估任务（模考）
                               ↓
                  得分 + 评分理由 + 运行时指标
```

| 要素 | 责任 |
| --- | --- |
| 评测集 | 提供 input、reference_output 及 context 等评估字段 |
| 评估对象 | 智能体、工作流或评测集数据本身 |
| 评估器 | 定义评估维度、输入变量、评分规则和输出格式 |
| 评估任务 | 组合上述要素，执行采样/调用/打分并生成报告 |

## 2. 在线评估与离线评估

| 维度 | 离线评估 | 在线评估 |
| --- | --- | --- |
| 阶段 | 开发、上线前、版本回归 | 生产运维、持续质量监测 |
| 数据源 | 已发布评测集 | API 调用产生的 Trace |
| 核心要素 | 评测集 + 评估对象 + 评估器 | 评估对象 + 评估器 + 采样策略 |
| 是否运行智能体 | “评估智能体”模式会运行；“评估评测集”模式不运行 | 由线上 API 调用自然触发 |
| 适合问题 | 标准问答、版本对比、数据质量、回归 | 真实流量、RAG 中间 context、工具 Span、轨迹质量 |
| 重要限制 | 只能选择评测集最新已发布版本 | 控制台调试不触发；必须有 Trace 上报 |

离线的两种模式：

- **评估智能体**：将评测集 input 逐条发送给智能体，生成 `actual_output`，再与 `reference_output` 对比。
- **评估评测集**：不运行智能体，直接评判评测集已有数据质量；适合日志导出数据、外部数据或更换评估标准后重评。

## 3. 评测集设计

### 字段跟着评估目标走

| 评估目标 | 建议字段 | 评估器示例 |
| --- | --- | --- |
| 常规问答正确性 | `input`、`reference_output`，运行时生成 `actual_output` | 正确性 |
| RAG 幻觉 | `input`、`reference_output`、`context` | 幻觉现象 |
| 文案格式 | 带明确排版指令的 `input`，通常不需要参考答案 | 格式检查 |
| 工具调用 | 工具轨迹、工具名和参数等在线 Span 变量 | 工具选择质量、工具参数正确性 |
| 多轮对话 | 完整 turns 或轨迹变量 | 轮次相关性、知识保持、对话完整性 |

开发期每个业务场景建议准备 30-50 条典型数据，覆盖正向、对抗/拒答和意图模糊边界。运营期将真实 Trace BadCase 持续回流。

### 容量与版本约束

| 限制 | 值 |
| --- | --- |
| 单个评测集列数 | 最多 50 |
| 单个评测集数据项 | 最多 5000 |
| 单次手动添加 | 最多 10 条 |
| 评测集数量 | 最多 100 |
| 单集容量 / 总容量 | 50 MB / 1 GB |
| 多轮评测集每个数据项 | 最多 10 轮 |

评测集只有提交为正式版本后才能用于评估任务。编辑后状态会变为“修改未提交”，需重新发布。版本号格式为 `a.b.c`，每段 0-999，新版本应大于历史版本。

### AI 合成评测数据

AI 合成可基于已提交的种子评测集进行语义泛化、风格迁移、场景扩展和质量筛选，用于补齐长尾、对抗、边界和安全红线样本。

- 仅支持 String 类型字段；基础版最多创建 1 个智能合成任务。
- 多轮合成的列名必须严格为 `input` 和 `reference_output`。
- 合成数量为 1-500；建议不超过种子数据的 10 倍，避免相似度过高和多样性不足。

## 4. 评估器

### 判定机制

| 类型 | 机制 | 适用任务 |
| --- | --- | --- |
| 模型判定 | 大模型按 Prompt 对语义一致性、完整性和逻辑性打分 | 非确定性、开放文本、对话和创意内容 |
| 代码判定 | 正则、JSON 解析、数学计算等确定性逻辑 | 格式、结构、数值和精确匹配 |
| 自适应判定 | 大模型将自然语言规则转换为结构化评估步骤 | 非技术运营人员、简单业务规则 |

自定义模型判定支持单轮和多轮对话。运营运维文档所述版本中，选择模型仅支持 `deepseek-v3.2`；多轮文本变量必须为 `turns`，多轮轨迹必须使用系统预置轨迹变量。自适应判定只支持单轮、离线评估，最多 10 条评分规则。

### 预置评估器支持矩阵

| 任务支持 | 模型判定 | 代码判定 |
| --- | --- | --- |
| 仅离线 | 轮次相关性、知识保持、对话完整性、参考答案遵从度、Skill 完整度、Skill 相关性、Skill 威胁分析、Skill 声明对齐、Skill 设计质量 | 文本等值判断、文本包含判断、文本正则匹配、文本起始子串判断、文本 JSON 格式校验、数学表达式相等判断、JSON 相等判断 |
| 仅在线 | 轨迹质量、工具参数正确性、工具选择质量、轨迹-工具参数填充正确性、主题遵从、角色遵从 | - |
| 离线 + 在线 | 正确性、AI 味检查、任务完成度、不敏感性、争议性、创意性、幻觉现象、性别歧视、恶意性、指令遵从度、拒答检测、格式检查、语种一致性、文本可用性、安全风险漏放、有害性、有用性、深度性、犯罪性、引用相关性、知识问答-指令遵循、知识问答-真实准确、知识问答-精炼性、知识问答-便捷性、知识问答-丰富度、简洁性、细节丰富度、角色违规、Rubric 评估、**Token 效率** | - |

**预置评估器总计 52 个**（0916 官方章节 2.5.4.2.1 – 2.5.4.2.52）。按用途分组速查：

| 分组 | 评估器 |
| --- | --- |
| **通用质量** | 正确性、任务完成度、指令遵从度、格式检查、语种一致性、文本可用性、简洁性、细节丰富度、创意性、深度性、有用性 |
| **对话与多轮** | 对话完整性、轮次相关性、知识保持、主题遵从、角色遵从、角色违规、Rubric 评估 |
| **RAG / 知识问答** | 幻觉现象、引用相关性、知识问答-指令遵循、知识问答-真实准确、知识问答-精炼性、知识问答-便捷性、知识问答-丰富度、AI 味检查 |
| **工具与轨迹** | 轨迹质量、工具参数正确性、工具选择质量、轨迹-工具参数填充正确性 |
| **Skill**（Managed Agents / Skill 场景） | Skill 完整度、Skill 相关性、Skill 威胁分析、Skill 声明对齐、Skill 设计质量 |
| **安全与合规** | 不敏感性、争议性、性别歧视、恶意性、安全风险漏放、有害性、犯罪性 |
| **成本效率** | **Token 效率**（0916 新增） |
| **确定性代码判定** | 文本等值判断、文本包含判断、文本正则匹配、文本起始子串判断、文本 JSON 格式校验、数学表达式相等判断、JSON 相等判断 |

场景选择建议：RAG 使用"知识问答-真实准确 + 知识问答-精炼性 + 引用相关性"；内容安全使用"恶意性 + 犯罪性 + 性别歧视 + 安全风险漏放"；工具调用使用轨迹/工具类评估器；通用对话使用"正确性 + 对话完整性 + 指令遵从度"；**Skill 场景**使用 Skill 五件套；**成本敏感场景**加 Token 效率。评估器不是越多越好，应由评估目标决定。

官方《最佳实践》另有专章可直接复用：4.1 智能体评估方法、4.2 评测集设计实践、4.3 **评估器最优组合实践**、4.4 企业知识问答助手（RAG）智能体评估、4.5 复杂工具调用智能体评估。

## 5. 创建评估任务

### 通用前置与配额

- 智能体、评测集和自定义评估器必须使用已发布版本。
- 必须开启数据上报，并开通/授权 APM 和 AOM。
- 最多创建 10 个在线+离线评估任务；每个任务最多 5 个评估器。
- 评估任务仅支持“智能体管理”中创建的智能体，不支持本地/外部接入智能体。
- 在线评估只支持自定义“模型判定”评估器和兼容的预置评估器。

### 离线任务流程

1. 进入“运营运维 > 评估 > 评估任务 > 创建评估任务”，选择“离线评估”。
2. 选择立即或稍后执行，按需开启“智能分析”。
3. 选择“智能体”或“评测集”作为评估对象。
4. 选择已发布评测集和评估器。
5. 核对字段映射：评测集 `input` -> 评估器 `input`，智能体实际输出 -> 评估器 `actual_output`，参考答案 -> `reference_output`。
6. 发起任务并等待成功或部分成功。

### 在线任务流程

1. 选择已发布智能体版本。
2. 选择评估粒度：整条调用链、模型、Root Span 或工具。
3. 配置 Trace 筛选条件、采样比例、采样总数上限、时间范围和重复频率。
4. 选择与粒度匹配的评估器，发起任务。
5. 用 API 调用智能体，等待采样条件达到后自动评估。

在线参数边界：会话持续时间默认 10 分钟、范围 1-60；采样总数默认 500、范围 1-500；历史 Trace 最多回流最近 30 天；采样数和采样比例过低可能导致无数据。

## 6. 评估报告、人工校准与回流

评估结果从宏观到微观包含：

- 数据级：原始输入、智能体实际输出、预期输出、评估器得分和评分理由。
- 报告级：平均分、最高分、最低分、总分、各评估器指标、模型调用耗时与 Tokens。
- 智能分析：开启后由大模型总结综合得分、问题排行、缺陷依据和修改建议；会消耗 Tokens。
- 人工校准：修正评估器误判的得分和理由；校准值会覆盖原始评分并影响统计。
- 人工标注：每条评估数据最多 5 个标注；最多创建 500 个标注；分类标注最多 20 个选项。
- 结果回流：可新建评测集或追加/全量覆盖已有评测集，用高分样本构建黄金集，用低分样本构建 BadCase 问题库。

详细的迭代和回归策略见 [优化闭环](optimization.md)。

## 7. 费用边界

- 评估任务中，**评估器运行**产生的 Tokens 由评估模块预置的专属资源承担，不消耗用户自购 Tokens。
- 离线“评估智能体”会实际调用智能体回答问题，这部分 Tokens 按智能体正常规则计费或消耗用户资源额度；“评估评测集”不运行智能体。
- 创建、使用或调试自定义模型判定/自适应判定评估器时，文档另有 MaaS 模型调用费用说明。它与任务执行阶段的预置评估资源不是同一环节，实际账单边界应以目标环境和当期计费页面为准。
- 智能分析会调用大模型生成总结与优化建议，应纳入评估成本预算。

## 8. 评估验收清单

- [ ] 先定义评估目标，再选评估器和数据字段
- [ ] 评测集覆盖正向、对抗和边界场景，并已发布正式版本
- [ ] RAG 幻觉评估含 `context`，工具评估选择“工具”粒度和轨迹类评估器
- [ ] 评估器字段映射经样本验证，未把 `reference_output`、`actual_output` 或 `context` 映射错位
- [ ] 在线评估由 API 调用触发，数据上报、APM/AOM 授权和采样范围均正确
- [ ] 人工复核低分、争议和高影响样本，不把 LLM 裁判当作无需校准的真值
- [ ] 优化后使用同一评测集和评估器做对比/回归测试
