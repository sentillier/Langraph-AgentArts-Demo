# 智能体安全（Agent Security）

> **信息来源说明（务必先读）**：本文混合两类信息，正文用徽标区分，**不可混用**。
>
> - 🟢 **【官方】** —— 已从 `AgentArts原始材料-0916` 检索到原文依据，含分册与章节位置。
> - 🟡 **【需求方输入】** —— 来自项目需求方，**尚未在 0916 官方材料中检索到对应条目**，属于待补充确认项，不得作为官方能力对外承诺。
>
> **官方材料基线**：0916《托管与运行智能体》**4.4 权限与访问控制**（含 4.4.1 委托介绍、4.4.2 入站身份认证）、《计费说明》第 3 章「关联服务」、「低代码开发智能体」发布部署流程「智能体卫士」参数、《观测与优化智能体》AI 合成数据「安全合规与红线探测」与预置评估器安全合规类。

## 1. 三层安全框架

| 层 | 关注什么 | 关键手段 | 信息来源 |
|---|---|---|---|
| **开发态安全** | 进生产之前，制品与技能包是否干净 | 容器镜像安全扫描、Skills 安全扫描 | 🟡 需求方输入（官方材料未检索到） |
| **运行态防护** | 跑起来之后，行为是否越界 / 是否被绕过 | 高危操作检测与阻断、意图行为一致性检测、角色限定 | 🟢 部分官方（智能体卫士 AI Defender）+ 🟡 部分需求方输入 |
| **AI Infra 安全** | 底座的 AI 资产与漏洞是否看得见、管得住 | AI 资产识别、AI 漏洞管理、Openclaw 应用基线检查 | 🟡 需求方输入（官方材料未检索到） |

**三层的关系**：开发态是**准入闸门**（不干净的制品不进生产），运行态是**行为护栏**（进来了也不能乱来），AI Infra 安全是**底座治理**（底座的资产、漏洞、基线的持续可视与可控）。三层缺一层，另外两层的效果都会被削弱。

> ⚠️ **重要澄清**：很多资料会把"智能体安全"等同于运行态防护。**只做运行态防护是不够的**——镜像里的漏洞、Skill 包里的恶意指令，在运行态看起来都是"正常调用"，护栏不一定拦得住。

## 3. 运行态防护

### 3.1 智能体卫士 AI Defender 🟢

**官方定位**：作为**智能体安全防护平台**，提供智能体**运行时**安全防护能力。

| 项 | 官方口径 |
|---|---|
| 三大能力 | **高危操作阻断**、**意图行为一致性检测**、**角色限定** |
| 生效方式 | 开启后**实时检测智能体执行链路与操作轨迹，监控全量行为并识别安全异常** |
| 开启位置 | 智能体**发布/部署**流程的观测配置区（与"指标""调用链"并列的参数项） |
| 默认状态 | **默认关闭**（需显式开启） |
| 风险规则与检测记录 | 在**企业主机安全 HSS** 中管理及查看（不在 AgentArts 控制台内） |
| 计费 | 列为**完全免费**的依赖服务；HSS 的智能体卫士**当前为公测阶段，暂不收费** |
| 前置条件 | 需在**授权管理 → 周边依赖服务**中开通；**未开通则无法进行智能体安全防护**（功能不可用） |
| 官方材料位置 | 计费说明 3「关联服务」；开始使用「开通服务」；资源与成员管理 3「授权管理」；低代码开发智能体（单智能体 / 工作流 / 多智能体）发布部署参数；最佳实践 6 |

**⚠️ 版本澄清（重要）**：智能体卫士 **在 0804 材料中即已存在**（0804 计费说明 3、开始使用、最佳实践、低代码开发均有条目）。它**不是 0916 新增能力**，而是**此前知识包构建时的遗漏项**。此前的知识包与《整体架构设计v1/v2》完全未覆盖运行态安全防护，本次为补齐。

**⚠️ 覆盖范围待实测（关键缺口）**：官方材料中 Defender 的开启入口出现在**低代码开发**（单智能体 / 工作流 / 多智能体）的发布部署流程；**高代码开发（智能体运行时）是否同样提供该开关，0916 材料中未检索到明确条目**。DemoAgent 走的是高代码运行时路径，因此这条必须**在实验局实测确认**，不能假设可用。

### 3.2 数据来源两条通路

需求方给出的两条通路，与官方"实时检测执行链路与操作轨迹"的描述方向一致：

| 通路 | 机制 | 时效 | 用途 |
|---|---|---|---|
| **API 接入** | 实时获取智能体上下文与产物 | 实时 | 在线拦截：高危操作检测与阻断、角色限定 |
| **可观测获取 Trace** | 从可观测数据中拉取 trace | 离线 | 离线安全评估：意图行为一致性、越界行为回溯、安全基线与趋势分析 |

🟡 **待补充**：① Defender 的实际接入 API（接口名、鉴权方式、数据 schema、是否走 URN / AgentIdentity）官方材料中**未给出**；② 实时通路是"旁路检测告警"还是"串联阻断"（是否会引入调用延迟、是否有超时降级策略）**未说明**；③ trace 拉取的范围、留存与采样**未说明**。

**架构含义**（基于现有信息的合理推断，需实测验证）：
- 实时阻断若为**串联**，则 DemoAgent 的**高危工具（文件写入、命令执行、外部网络调用、删除类 MCP Target）必须纳入角色限定范围**，否则护栏形同虚设。
- 离线评估依赖 **trace 完整性**：若 DemoAgent 的 `@app.entrypoint` 内未透传 `session_id` / 用户身份，或工具调用未产生 Span，则离线安全评估会**看不到完整链路**。这条要求与 [可观测性](../07-operation/observability.md) 的接入要求一致。

### 3.3 权限与访问控制：官方称其为"智能体运行时的安全底座" 🟢

官方原文：**权限与访问控制是智能体运行时的安全底座，约束智能体可以做什么、访问哪些资源、谁可以调用智能体，防止越权、数据泄露、恶意操作。**

| 组成 | 官方内容 | 详见 |
|---|---|---|
| **委托** | 运行时涉及两个委托：`AgentArtsRuntimeDeploymentAgency`（服务部署委托，**必须·不可删**）与**用户运行时委托**（智能体身份委托，默认 `DefaultAgentArtsRuntimeAgency`）；委托**创建后可按最小权限授权** | [identity.md](../05-identity/identity.md) §2.1 |
| **URN 与智能体身份** | 运行时在「权限与访问控制」区域暴露 **URN**；凭 URN 到 **AgentIdentity 智能体身份服务**获取 API Key | 托管与运行智能体 4.4.2 |
| **入站身份认证** | 三方式：IAM 认证（IAM 用户名）/ API Key 认证（自动创建并绑定）/ OAuth 2.0 认证（Discovery URL、允许的受众/客户端/范围）。**认证方式创建后不可修改**；**调用方必须使用与运行时一致的认证方式，否则请求被拒绝** | [identity.md](../05-identity/identity.md) §2.0 |
| **出网配置** | 创建后**不可编辑** | Managed Agents 4.4 / 托管与运行智能体 4.10 |

> ⚠️ **易踩坑**：入站认证选错**不能改**，只能"复制"运行时重建。设计阶段必须一次性确认调用方类型。

### 3.4 安全护栏 Rails（低代码形态）🟢

官方错误码体系（`低代码开发智能体` 第 9 章附录）**反证了三层护栏的存在**：

| 层 | 官方错误码与场景 | 说明 |
|---|---|---|
| **输入护栏** | `AgentArts.101048` —— "在对用户输入进行安全检查（自定义输入护栏）时发生异常，导致无法判断内容是否合规" | 用户输入进入模型前的检测 |
| **执行护栏** | `AgentArts.101049` —— "组件执行过程中的特定安全检查环节触发了自定义护栏逻辑异常" | 工具/组件执行时的校验 |
| **输出护栏** | `AgentArts.101050` —— "系统内置的默认安全护栏在处理组件输出结果时发生非预期崩溃" | 模型输出侧的**内置**护栏 |
| 护栏初始化 | `AgentArts.101047` —— "提问组件关联的安全护栏（Rails）模块无法加载配置或初始化引擎失败" | 护栏引擎的加载与配置 |

**术语**：官方在错误码中使用「**安全护栏（Rails）**」，并区分"自定义护栏"（用户脚本）与"系统内置默认护栏"。

🟡 **待补充**：该护栏体系目前**仅在低代码形态**有官方证据；**高代码运行时是否提供等价的 Rails 接口（可在 `@app.entrypoint` 前后挂自定义护栏）未确认**。

### 3.5 内容审核 🟢

官方能力：**通过设置关键词匹配处理输入输出内容，保障大模型内容安全**（输入审核关键词，每行一个）。

| 项 | 说明 |
|---|---|
| 机制 | 关键词匹配（**非语义模型**） |
| 位置 | 低代码开发「智能体组件」配置项 |
| 与 Rails 的关系 | 内容审核是**配置化关键词**层；Rails 是**可编程逻辑**层；两者互补 |
| 局限 | 关键词匹配对**同义改写、编码绕过、多语言混写**基本无效，不能作为唯一防线 |

### 3.6 安全评估（离线）🟢

平台已有可用于**安全维度**的评估能力，这是"从可观测获取 trace 做离线安全评估"最直接的官方落点：

| 能力 | 官方内容 | 位置 |
|---|---|---|
| **安全合规与红线探测**（AI 合成数据） | 用于内容安全测试、合规性验证、探测模型安全边界；定向合成涉及**隐私泄露、敏感话题、偏见歧视**等触及业务红线的试探性样本；**通过构建此类数据集，能够对应用的安全护栏进行测试** | 观测与优化智能体 AI 合成数据 |
| **合成对抗测试样本** | 聚焦**低频高危边界场景**（对抗性输入、极端边界条件、复杂逻辑链条），深度探测能力边界与薄弱环节 | 同上 |
| **预置评估器·安全合规类** | 安全维度评估器（如恶意性、犯罪性、性别歧视、安全风险漏放等），0.0–1.0 分制 | [evaluation.md](../07-operation/evaluation.md) §4 |
| 回流闭环 | 标注 → 评测集回流 → 评估 → 优化 | [optimization.md](../07-operation/optimization.md) |

**建议**：把"安全合规与红线探测"合成的样本**单独建一个安全评测集**，与功能评测集分开维护；安全类指标设**一票否决**（不参与加权平均），避免被功能高分掩盖。

## 7. 安全验收清单

> ⚠️ 因多项待补充，本清单分「现有能力可验收」与「待能力确认后验收」两组。

**现有能力可验收（🟢）**
- [ ] 运行时入站认证方式已确认且与调用方匹配；已试过错误认证方式会被拒绝
- [ ] 已知悉"入站认证创建后不可修改"，且设计阶段已一次性确认
- [ ] `AgentArtsRuntimeDeploymentAgency` 存在且未被删除
- [ ] 用户运行时委托已按最小权限授权（含 OBS 只读/读写所需 action）
- [ ] 出网配置、存储挂载等不可变更项在创建时已确认
- [ ] 代码执行走代码解释器；`execute_command` 的 shell 元字符被阻断
- [ ] 浏览器配置了域名白名单，高风险动作有人工接管路径
- [ ] 记忆库按 `actor_id` 隔离验证通过，不同用户 0 串扰
- [ ] 知识库未放入用户隐私数据
- [ ] Trace / 日志已脱敏，无 API Key / AK-SK / OAuth / STS Token
- [ ] 安全评测集已建立（含"安全合规与红线探测"与"合成对抗测试样本"），安全类指标为一票否决
- [ ] CTS 可检索到关键操作记录

**待能力确认后验收（🟡）**
- [ ] 智能体卫士已开通（授权管理 → 周边依赖服务），且**确认高代码运行时可否开启**
- [ ] 高危操作阻断实际触发验证（构造一次高危调用，确认被阻断且留痕）
- [ ] 意图行为一致性检测的告警可在 HSS 中查看
- [ ] 角色限定生效：越权工具调用被拒
- [ ] 实时通路时延与降级策略已实测
- [ ] 离线安全评估链路：从 trace 拉取 → 安全评估 → 输出安全报告
- [ ] 容器镜像安全扫描纳入 CI/CD 准入闸门
- [ ] Skills 安全扫描（上线后）纳入 Skill 上架准入
- [ ] AI 资产清单可导出，漏洞可闭环跟踪
- [ ] Openclaw 应用基线检查项全部通过
